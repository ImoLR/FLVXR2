## 已定设计（用户 2026-10-31 批准协调人方案）

- 用户落地节点（我们的服务器）可把流量交给用户**自己的外部节点**出去：客户端 → 我们的落地节点 → 外部节点 → 互联网。
- 外部节点 = 每用户自己的列表（上限 20，管理员不限），只在「链式代理」弹窗里管理（下拉 + 小管理列表：改名、删除）；
  添加方式「粘贴链接」/「从订阅导入」（只拉取一次、勾选导入、不自动同步、不保存订阅地址）。
- 封锁类规则照常先生效；节点的非封锁路由（直连 / WARP / 其他出站）被链式出站取代；外部节点不通时连接失败，**不回落直连**。
- 计费不变（落地照旧计费，链式不额外计费/计数）。
- 共享（妙妙屋）服务器只能用 Helper 现有白名单（SOCKS / HTTP / Shadowsocks AEAD·2022 / VLESS Reality），不改妙妙屋。

## 技术设计

### 数据（SQLite / PostgreSQL，AutoMigrate，有 `TableName()`，无 jsonb/serial）
- 新表 `landing_external_node`：user_id（索引）、name、protocol、host、port、summary（「协议 · 地址:端口」）、
  upstream（解析后的出站 JSON，含密钥，`json:"-"`，任何接口都不返回）、upstream_hash（索引，判重）、时间戳。
  每用户上限 20（`model.MaxExternalNodesPerUser`），管理员自己的列表不限；在用户行加锁的事务里判上限，并发也不会超。
- `landing_node.chain_external_id`（默认 0 = 直连）。只加列/加表，旧数据不变；回滚旧版面板无需恢复数据库
  （旧面板忽略新列和新表；已开启的链式在旧面板上会变回直连）。

### 出站编译（`internal/landingegress`）
- `NodeRef.Chain` / `ChainErr`：开启链式的节点各层（内置防滥用、全局·强制、节点、服务器、全局·默认）只保留**封锁**
  规则，最后加一条「该节点全部流量 → 外部节点出站」；非封锁规则（直连 / WARP / 代理 / 默认出站）对它不再生效。
  其他节点的规则逐字节不变（测试固定）。
- 出站 tag `flvxo-x<内容哈希 24 位>`：同一台服务器上相同的外部节点只建一个出站；改了节点 = 新 tag，沿用 107 的
  「先加出站 → 原子换规则 → 删旧出站」热更新，不重启 Core。
- 失败封锁：外部节点被删 / 协议不支持 / 服务器出站名额满（每台最多 8 个不同出站，模板先占）→ 该节点规则为封锁 +
  原因，**不回落直连**；整份计划编译失败时 `BlockPlan` 也覆盖链式节点；节点程序不支持出站计划时链式节点下发
  `enabled=false`；共享方收回「允许自定义出站与路由」时链式节点在 desired 里 `Enabled=false`。
- 保存前后各编译一次：会让任何其他节点的链式失效（占名额）的保存一律拒绝；管理员改模板 / 方案也同样检查。

### 节点程序（零改动，不需要 OTA）
- 原生节点程序现有的出站计划校验/渲染（plan 107/108 共用 `EgressOutbound.validate/render`）已支持 108 全部类型
  （VLESS tcp/ws/grpc + none/tls/reality、VMess AEAD、Trojan、SS/SS2022、SOCKS5、HTTP/HTTPS、Hysteria2），
  只要求 tag 形如 `flvxo-[a-z0-9]{1,32}`、每台 ≤ 8 个出站。TUIC / allowInsecure 在面板解析时就拒绝。
- 门槛：`landing_egress ≥ 1` 且 Core 已能热更新路由（`egress_ready` 或管理员已确认重启）；否则按钮灰、弹窗说明原因。

### 共享（妙妙屋）服务器（妙妙屋零改动）
- 只放 Helper 现有白名单：SOCKS5、HTTP（不含 HTTPS）、Shadowsocks AEAD / 2022、VLESS Reality（TCP）；
  以 plan 107 的字段形式下发（不带 network/security/tls… 字段，Helper 严格解码）。门槛 = 现有共享能力
  `egress.versions` 含 1 且 `allowed`。下拉里不支持的外部节点灰色「此服务器不支持该协议」。
- 共享服务器没有 FLVX 节点程序，不能检测；看 Helper 应用结果（同步中 / 已生效 / ⚠ 原因）。

### 接口（POST，`{code,msg,data,ts}`，原始 JWT）
- `/api/v1/landing/external/{list,parse,create,rename,delete}`；管理员带 `userId` 代节点所属用户操作。
- `/api/v1/landing/external/sub/fetch`：只拉一次（http/https、DNS 后只连公网地址且每跳重新校验并钉住 IP、≤3 次跳转、
  10 s、2 MB、每用户每分钟 5 次、通用 UA、不带 cookie/凭据、错误不含内部细节）；解析 Base64 / 链接列表 /
  Clash YAML（Clash 项转成分享链接再走同一个解析器）；自动过滤信息节点（剩余流量 / 到期 / 官网 / 套餐 … 和占位地址）。
  结果只在内存缓存（每用户 ≤3 份、全局 ≤64 份、10 分钟），按 fetchId + 序号导入；订阅地址不保存。
- `/api/v1/landing/external/sub/import`：域名在导入时解析并校验（并发 4、总 20 s）；判重 / 上限 / 失败分别报告。
- `/api/v1/landing/node/chain/{save,probe}`：外部节点必须属于落地节点的所属用户（管理员也一样）；保存时检查服务器能力、
  协议白名单、出站名额、原生 TCP 检测（不通则拒绝）；检测每用户每分钟 10 次。
- 地址校验复用 108：内网/回环/链路本地/CGNAT/组播/未指定/云元数据、面板地址、所有 FLVX 节点地址，**新增所有落地服务器
  公网地址**（共享服务器没有 FLVX 节点行）；域名任一解析结果命中即拒绝；大陆目标策略同普通规则。
- 删除正在用的外部节点 → 拒绝并列出落地节点名；转移开启链式的落地节点 → 拒绝（外部节点属于原用户）；删用户 → 一并删除。
- 计费不变：链式只改出口，落地照旧按入站总量计（双向 ×2 等），不额外计费或计数。

### 前端（只加不改）
- 落地卡片 / 管理员表格：新增「链式代理」按钮（蓝色浅底；服务器不支持且未开启时灰色，点开说明原因）；开启后用
  `链式 → 名称 · 协议`（青色）替换「出站：…」标签，同步中琥珀色，失败红色「⚠ 链式代理未生效」+ 一行原因。
- 链式代理弹窗：直连 / 走我的外部节点、外部节点下拉（可搜索）、+ 添加、检测、管理（改名 / 删除）、一行说明。
- 添加外部节点：「粘贴链接」/「从订阅导入」两个标签页。
- 路由规则弹窗顶部一行说明「已开启链式代理 …」，其余不变。
