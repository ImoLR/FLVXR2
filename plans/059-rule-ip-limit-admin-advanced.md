# 用户实时连接池、规则 IP 限额与管理员高级功能计划

## 范围

本轮只实现、测试、提交并推送分支，不发布、不打 tag、不部署、不升级 agent，也不修改生产数据：

- 规则保留可选 `max_connections`，新增可选 `max_client_ips`；两者分别限制单个入口 service 的活跃连接数和活跃来源 IP 数，`0` 表示不限。
- 现有 `user.max_connections` 改为用户所有规则、所有入口节点共享的实时活跃连接总额；新增 `user.max_client_ips` 作为相同范围内去重来源 IP 总额，`0` 表示不限。
- 同节点由 agent 的用户配额组严格共享计数；跨节点由 panel 汇总 agent 上报并在内存中计算、推送每节点预算。
- 规则表单的整个“高级功能”仅管理员可见；后端对非管理员提交的全部高级字段静默忽略。
- 用户管理增加总接入 IP 数限制，并在列表中显示 panel 内存汇总的“连接 X/Y · IP X/Y”。
- 保持旧 agent 和现有数据兼容；不实现静态份额分配，不按规则额度总和限制规则创建。

## 语义与兼容性

- 新规则的 `max_connections`、`max_client_ips` 均默认 `0`，永远不因用户池额度而拒绝创建；删除旧的“把用户总连接数复制到新规则”行为。
- 管理员设置的规则额度独立生效，不要求同一用户各规则额度之和小于总额。若对应用户总额大于 `0`，单条规则额度不得超过总额；用户总额为 `0` 时规则额度可为任意非负值。
- 非管理员创建规则时，高级字段采用系统默认：默认入口 IP、流量/连接/IP 限额为 `0`、无有效期，速度仍按现有用户/隧道默认逻辑计算。更新时保留所有已存高级值。
- agent 为每个入口 service 先检查规则额度，再检查节点内共享的 `quotaGroup`。来源 IP 取远端地址 host；同一已活跃 IP 的额外连接不消耗新的 IP 槽位，连接关闭时释放计数。
- service metadata 携带 `maxClientIps`、`quotaGroup`、`groupMaxConnections`、`groupMaxClientIps`。组预算使用 `-1` 表示不限、`0` 表示已满，避免和规则层 `0 = 不限` 混淆。
- fork.13 agent 每秒上报各配额组的活跃连接数和活跃 IP 集合。panel 按用户聚合所有在线节点；对节点 N：连接预算为“总额减去其他节点连接数”，IP 预算为“总额减去其他节点上、但 N 当前没有的 IP 并集大小”，结果最小为 `0`。
- IP 跨节点预算是有意偏严格的近似：已在其他节点计数的同一个 IP 首次连接 N 时仍占用 N 的本地预算；panel 下一轮汇总后收敛。
- panel 只在预算变化时向承载该用户入口 service 的在线节点批量发送一个 `SetQuotaGroups` 命令，每节点最多每秒一次；状态只存内存，不做周期性 DB 写入。
- panel 或节点重连时，service metadata 先带用户完整总额作为初始节点预算，随后数秒内收敛；该窗口可能短暂超额。已有连接不被清退，池释放后立即允许新连接。
- 已知版本不支持 fork.13 协议的节点不发送新命令；版本未知时允许命令失败并只记录一次，不向 UI 重复告警。旧 agent 忽略未知 metadata，继续使用现有 `maxConnections=0 -> user total` 的单 service 回退；实时用户池和 IP 限额只在 fork.13 agent 上生效。
- 既有规则数据不迁移、不重写。旧创建路径留下的 `max_connections = user total` 继续作为规则上限。
