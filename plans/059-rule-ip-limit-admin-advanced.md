# 规则接入 IP 限制、用户总额与管理员高级功能计划

## 范围

本轮只实现并测试以下内容，不发布、不打 tag、不部署、不升级 agent，也不修改生产数据：

- 为规则增加 `forward.max_client_ips`，在每个入口节点的每个 service 内限制同时活跃的不同来源 IP 数。
- 将 `user.max_connections` 作为该用户所有规则的总分配额度，并新增 `user.max_client_ips` 总额度；创建、更新规则时执行剩余额度和存量超配豁免规则。
- 仅管理员可见和修改规则“高级功能”；非管理员提交的高级字段在后端静默忽略。
- 在用户管理界面显示两类额度的已分配/总额及超配警告。
- 通过现有 service 配置同步把 `maxClientIps` 下发给 agent，并完成后端、agent 和前端验证。

## 语义与兼容性

- 规则的连接数和接入 IP 数分配在用户维度各自独立求和；规则值 `0` 在求和时计为 `0`。
- 用户某一总额大于 `0` 时，新规则未显式分配该维度（普通用户必然如此，管理员也可留空/填 `0`）会取得全部剩余额度；没有剩余额度则拒绝创建。管理员显式值必须在 `1..剩余额度`。
- 更新存量规则时，未改变或降低分配值即使用户已超配也允许；提高时按排除当前规则后的剩余额度验证。降低用户总额到低于当前分配仍允许，并在管理界面告警。
- 用户某一总额为 `0` 时，该维度不受总额约束；规则值 `0` 表示不限，任意非负值均可保存。
- 保留控制面现有的连接数兼容回退：存量规则 `maxConnections=0` 时仍使用用户连接总额；接入 IP 数不增加该回退，`0` 始终表示不限。
- 多入口隧道中，规则分配值在用户总额中只计算一次，但限制在每个入口节点的 service 上分别执行，不做跨节点协调。
- 旧 agent 会忽略未知的 `maxClientIps` metadata；混合版本期间只有运行 fork.13 agent 的入口节点执行接入 IP 数限制。
